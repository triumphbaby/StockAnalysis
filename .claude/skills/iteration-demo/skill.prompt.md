# 迭代成品演示

你需要展示指定迭代的完整可用功能。

## 输入

- 迭代编号（如果未指定，则展示最新迭代）

## 执行步骤

### 1. 确定迭代编号

如果用户指定了迭代编号，使用该编号。否则，查找项目中最新完成的迭代。

查找方法：
- 检查 `ITERATION_*_SUMMARY.md` 文件
- 查看 `PROJECT_STATUS.md` 中的当前迭代
- 从最大编号开始检查

### 2. 检查服务状态

```bash
# 检查后端服务
curl -s http://localhost:8000/health

# 检查前端服务
curl -s http://localhost:3000 | head -10
```

如果服务未运行：
- 提示用户服务未启动
- 提供启动命令
- 询问是否需要启动服务

### 3. 读取迭代文档

读取以下文件（如果存在）：
- `ITERATION_N_SUMMARY.md` - 迭代总结
- `openspec/changes/` - 相关变更记录
- `PROJECT_STATUS.md` - 项目状态

### 4. 提取功能清单

从迭代文档中提取：
- 新增的前端功能
- 新增的后端API
- 数据库变更
- 技术栈更新

### 5. 验证端到端链路

对每个功能进行验证：

**前端功能**：
- 访问相关页面URL
- 确认UI组件可见
- 测试交互功能

**后端API**：
- 测试API端点
- 验证响应格式
- 检查数据正确性

**数据流**：
- 确认前端可以调用后端
- 验证数据正确传递和展示

### 6. 生成演示指南

创建包含以下内容的演示文档：

```markdown

## 服务状态
- 前端: [状态] [URL]
- 后端: [状态] [URL]

**访问方式**: [URL或操作步骤]
**演示步骤**:
1. [步骤1]
2. [步骤2]
...

**预期效果**: [描述]

### 功能2: [名称]
...

## API测试

### API 1: [端点名称]
\`\`\`bash
curl [命令]
\`\`\`
**预期响应**:
\`\`\`json
{...}
\`\`\`

## 完整性检查

- [ ] 所有前端功能可访问
- [ ] 所有API正常响应
- [ ] 端到端流程完整
- [ ] 文档齐全

[列出本迭代的技术亮点]

## 已知问题

[列出已知问题和限制]

## 下一步计划

[下个迭代的简要说明]
```

### 7. 输出格式

输出应包括：

1. **执行摘要**（简短）
   - 迭代编号和名称
   - 主要功能数量
   - 服务状态

2. **功能演示**（详细）
   - 每个功能的访问方式
   - 详细演示步骤
   - 截图说明（如适用）

3. **技术验证**（技术性）
   - API测试结果
   - 性能指标
   - 测试覆盖率

4. **文档链接**
   - 相关文档路径
   - 外部资源链接

## 注意事项

1. **服务检查优先** - 如果服务未运行，先提示启动
2. **验证完整性** - 必须确认前后端链路完整
3. **提供实例** - 给出具体可执行的演示步骤
4. **记录问题** - 如发现问题，明确记录
5. **生成文档** - 创建标准化的演示报告文件

## 错误处理

如果遇到以下情况：
- **服务未运行**: 提供启动指南，询问是否启动
- **功能异常**: 记录问题，继续检查其他功能
- **文档缺失**: 使用现有信息，标注缺失部分
- **API失败**: 提供错误详情，给出排查建议

## 成功标准

演示完成后，用户应该能够：
1. 清楚知道该迭代新增了哪些功能
2. 能够立即访问和使用这些功能
3. 理解如何测试验证功能
4. 获得完整的演示文档
